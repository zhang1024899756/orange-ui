# 主题定制

主题是这套组件库**最值得说的一件事**。4 套内置主题 × 明暗两版，全部由 CSS 变量驱动；
换主题只改 `<html>` 上的两个属性，**不重新编译、不做 JS 注入、SSR 不闪白**。

## 一条属性就切换

```html
<!-- 整站 -->
<html data-oui-theme="orange" data-oui-scheme="light">

<!-- 或者任何局部容器：同一页里可以并存两套主题 -->
<section data-oui-theme="violet" data-oui-scheme="dark"> … </section>
```

- `data-oui-theme`：`orange` / `violet` / `teal` / `rose`，或你自己注册的名字
- `data-oui-scheme`：`light` / `dark`；**不写**时跟随 `prefers-color-scheme`

:::tip 用 data-* 而不是 class
`class="dark"` 这种名字几乎一定会和宿主项目撞车。data 属性是私有命名空间，也方便脚本操作。
:::

## React 里切换

```tsx
import { ThemeProvider, Button } from '@arvinzxy/orange-ui';

// 只管自己这片区域（默认）
<ThemeProvider theme="teal" scheme="dark">
  <Button>青屿暗色</Button>
</ThemeProvider>

// 写回 <html>，整站生效
<ThemeProvider theme="rose" scheme="light" global>
  <App />
</ThemeProvider>
```

## 自定义品牌色

一个主色能改的东西比想象中少。它喂给的是几个**能现算**的变量：浅底 `-subtle`（本色 10%）
与描边 `-border`（本色 32%）由 `color-mix(in srgb, …)` 算出来。剩下的几档是**明文值**，
不给就沿用内置主题的：`-hover` / `-active`、当文字用的 `-ink`，以及 0.2.0 多出来的
`-solid`（实心背景专用）。少给哪一档，对应形态就会「串回」蜜橘主题，看着像没换干净。

所以换成自家品牌最省事的写法是：

```css
/* 姿势 A：注册一个新主题 */
[data-oui-theme='my-brand'] {
  --oui-color-primary: #0EA5E9;
  --oui-color-primary-solid: #0378B4;        /* 实心底：白字 4.83（主色压白字只有 2.77） */
  --oui-gradient-brand-2: #3DD4BE;
}

/* 姿势 B：局部覆盖，只影响某个区块，不污染 :root */
.pricing-card { --oui-color-primary: #7C3AED; --oui-radius-md: 6px; }
/* #7C3AED 压白字本身就有 5.70，实心档可以直接等于主色 */
```

实心档怎么解：把品牌色压深，直到白色文字 ≥ 4.5:1。上面两个数是量出来的
（`#0EA5E9` 压白字 2.77 → `#0378B4` 4.83）。

React 里（姿势 C）：**只给 `primary` 就够了**。`ThemeProvider` 会在运行时把实心档算出来——
保持色相与饱和度、压低明度到白字刚好 ≥4.5:1，hover / active 再按同一套比例（92% / 86% 保留）派生：

```tsx
// 一个值跑完整条链路：fill 用 #00AA88，实心档自动压到白字达标的深一档
<ThemeProvider primary="#00AA88" primary2="#3DD4BE"> … </ThemeProvider>
```

`#00AA88` 压白字只有 2.96，自动派生会给出 `#00806A`（4.89）。想精确控制品牌色在实心大块上的
深浅时，再显式传 `primarySolid`：

```tsx
<ThemeProvider primary="#00AA88" primarySolid="#00806A"> … </ThemeProvider>
```

这条派生是纯函数（`deriveSolidColor`），服务端与客户端结果一致，不会造成水合不一致；
但**纯 CSS 写法（姿势 A / B）没有这层兜底**，那里必须自己把 `-solid` 写上。

:::note 哪些是现算的，哪些是写死的
浅底与描边现算，所以换品牌色**不需要构建脚本生成色阶**——这也是它比 antd（主题编译进包）更轻的原因。
但 hover / active / ink / solid 是明文值：它们得靠「和底色的对比度」反解，跑在 CSS 里就成了猜色，
所以在 `tokens.css` 里逐套主题写好。
:::

## 派生规则（写死的，别自己调）

| 层 | 项 | 规则 | 为什么 |
|---|---|---|---|
| fill | hover / active | 规则是基色混 8% / **14%** 黑，每套主题按它算好后写成明文值 | 组件内部的实心 hover 走 solid 档，不取这里 |
| fill | 浅底 subtle | 本色 10% 透明 | 与主色同源 |
| fill | 浅底上的文字 | 用对应的 `*-ink` | 本色当文字只有 3.0–3.6:1 |
| fill | 描边 / 焦点环 | 本色 32% 透明 | |
| solid | 三档 | 逐档写死，**不做 color-mix** | 深色方案的 `--oui-color-shade` 是白色，混色会把实心档提亮、白字跌破 4.5:1 |
| solid | 上面的字 | `--oui-color-on-solid` = `#FFFFFF` | 全库唯一取值；中性色例外见 [设计变量](/design/tokens) |

## 实心背景上的字：恒白字，为此每套主题配一条实心档

0.2.0 的结论只有一句：**实心背景上的字永远是白色**（`--oui-color-on-solid`，`#FFFFFF`，全库唯一取值），
不为某套主题单独换成墨色。为了让它成立，每套主题多给一条**实心档**——把品牌色压到
「白色文字刚好 ≥4.5:1 的最浅一档」：

| 主题 | primary（fill，仍是品牌色） | solid（实心档） | 白字对比度 |
|---|---|---|---|
| orange 蜜橘 | `#F26B21` | `#C74F0A` | 4.61:1 |
| violet 紫罗兰 | `#624AFF` | `#624AFF` | 5.33:1 |
| teal 青屿 | `#0E9384` | `#0C8376` | 4.64:1 |
| rose 珊瑚 | `#E5446D` | `#E02353` | 4.63:1 |

hover 与 active 各再深一档（4.60–6.71 全区间都过线），见 [设计变量](/design/tokens)。

**这是一个可测量的取舍，不是偏好。** 0.1.x 走的是相反的路：保留原品牌色，把字换成墨色
（orange `#232038` 5.17 / teal `#1A1728` 4.62 / rose `#181522` 4.60）。
两条路都能过 AA，但代价不同：

- 换字色：品牌色原样保留，可是同一个按钮在 orange 上是深字、在 violet 上是白字——
  两套主题之间的「性格」不一致，且深字让按钮看起来偏轻。
- 换底色（现在这条）：所有实心件的字都是白，观感和交互反馈统一；代价是蜜橘从
  `#F26B21` 压到 `#C74F0A`（青屿 `#0E9384` → `#0C8376`、珊瑚 `#E5446D` → `#E02353`），
  品牌色在实心大色块上比在图标/描边上深一档。

**violet 是唯一没让步的主题**：`#624AFF` 压白字本来就有 5.33，实心档直接用原色。
深色方案下实心档也不重新取值（白字要的是背景足够深，与页面底色无关），变亮的是
fill 与 ink——它们负责描边、图标和文字。

:::caution 中性色是例外
黑/白按钮、中性徽章没有「压深换白字」的余地：亮色用深底白字（`#27254C` 底，14.43:1），
暗色反转成浅底深字（`#F2F3F8` 底 + `#12131A` 字，16.71:1）。白字压浅底物理上不可能到 4.5:1，
所以这一档的文字色由 `--oui-color-on-neutral` 跟随明暗反转。
:::

## 防止首屏闪白

暗色用户刷新时闪一下白，是唯一一个「删不掉」的体验缺陷——水合时序不会因为你改 React 代码而改变。
做法是在 `<head>` 里放一段**同步内联**脚本，比任何 CSS 都早：

```html
<script>
  (function () {
    try {
      var t = localStorage.getItem('oui-theme');
      if (t === 'system') {
        t = matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light';
      }
      if (t) document.documentElement.setAttribute('data-oui-scheme', t);
    } catch (e) { /* Safari 无痕下 localStorage 会抛 */ }
  })();
</script>
```

三条纪律：**同步、内联、放 head 最前面**。任何 defer / 外部文件 / `useEffect` 都太晚。
`ThemeProvider` 首帧只读 DOM 上已经写好的属性，不重算——否则水合后必然闪一次。

## 覆盖组件内部样式

类名是**稳定语义类名**（`.oui-button`、`.oui-tag`），不是哈希。所以你有两条路：

```css
/* 1. 只改变量（推荐） */
.my-app { --oui-button-height-md: 34px; }

/* 2. 直接改选择器 —— 不需要 !important */
.my-app .oui-button { letter-spacing: 0.02em; }
```

:::caution @layer 的代价
组件样式全部在 `@layer oui.components` 里，所以**你任何未分层的普通 CSS 都能盖过它**——
这是故意的。但反过来，如果你把 reset 写成未分层的 `button { background: none }`，
它也会盖掉我们的按钮样式。建议把宿主项目的 reset 放进 `@layer reset`。
:::
