# 设计原则

## 1. 密度优先于呼吸感

社区/工作台类界面一屏要放 20–30 条信息。控件 32px、元信息 12px、行内 gap 8px——
把正文放到 16px、控件放到 40px，它立刻变成后台管理系统。

**代价要认**：这种密度在阅读型页面（文章、文档）上会显得挤。所以正文默认仍是 14px，
真正需要阅读的地方自己放大。

## 2. 活泼只能从一处来

彩色只出现在 **16px 图标**和**品牌渐变**里。中性色的 chip 里塞一个彩色小图标，
是这套视觉「年轻」的全部来源——不是彩色大色块，不是渐变文字，不是发光阴影。

一旦允许第二个地方用彩色，第三个就会出现，最后整页都是颜色，什么也不突出。

## 3. 阴影是浮层的专属信号

静态卡片零阴影、1px 边框。阴影只表示「这一层浮在内容之上」：Dialog、Tooltip、Dropdown。
把阴影当装饰用，等于让用户分不清什么是浮层。

## 4. 加载态不改变布局

按钮 loading 锁宽、数值用同高骨架条、图片用 `aspect-ratio` 先占位。
布局跳动是「看起来卡」和「看起来稳」的分界线——而它恰好最容易被忽略，
因为只有慢网络下才会暴露。

## 5. 能用 CSS 变量表达的，就不留给 JS

主题切换、尺寸、圆角、间距全部走 CSS 变量，所以：换主题不重渲染、不需要 JS 注入、
SSR 首屏就是对的。**能交给 CSS 的事交给 CSS**，运行时只留交互状态。

## 6. 无障碍是硬约束，不是加分项

对比度是算出来的（不是挑颜色时顺便看一眼）；禁用态按 WCAG 1.4.3 豁免（而不是硬凑到 4.5 让禁用态变黑）；
命中区用伪元素补到 24×24（而不放大视觉尺寸）。每条都能在源码里指出来。
